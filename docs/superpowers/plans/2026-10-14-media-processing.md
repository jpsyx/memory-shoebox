# Media Processing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Repair missing previews and generate economical photo/video copies while preserving originals and serving availability.

**Architecture:** SQLite owns a fenced, durable processing queue and output ownership. A single worker uses metered B2 input, isolated subprocesses, bounded scratch storage, and streaming multipart output. Publication checks the current source and lease in a transaction; cleanup uses the same ownership gate.

**Tech Stack:** Existing Node/Kysely/S3 SDK/Sharp, Linux cgroup v2, FFmpeg/ffprobe, libheif tools, Vitest, local fake bucket.

**Spec:** [Approved design, sections 7-8](../specs/2026-10-14-media-loading-design.md).

## Global Constraints

Inherit the [master constraints](2026-10-14-media-loading.md#global-constraints), including every numeric processing limit. No network/subprocess work occurs in a database transaction. Original archival succeeds independently of derivative work. Linux hard-limit capability must be detected; a Docker container's total memory limit alone does not isolate the API from its worker.

## Review Focus

Master focus 4 belongs here. Additional tests cover source replacement during processing, multi-image HEIC primary selection, HDR/rotation, source responses that ignore Range, and capability failure under a 512 MiB deployment. A disabled runtime is an explicit supported state, not proof that codec processing works.

## File Structure

`apps/server/src/mediaProcessing/queue/` owns catalog transitions; `input/` owns the local range reader; `runtime/` owns admission, subprocess isolation and shutdown; `recipes/` owns media transformations; `output/` owns publication/cleanup. Keep these as separate modules with dependency-injected clocks and storage/process adapters. Corresponding tests live under `apps/server/test/mediaProcessing/`. Only B1 changes schema; B5 integrates the worker into app lifecycle.
