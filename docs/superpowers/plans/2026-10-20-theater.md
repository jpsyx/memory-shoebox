# Shared Theater Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Ship the approved shared photo/video theater using the existing media and conversation components.

**Architecture:** Keep one persistent fullscreen host at `ItemSurface`, and one rendered viewer tree whose presentation changes through props. Keep conversation writes and playback ownership in their existing hooks; add shared per-item draft memory and a presentation-only comment dock. A separate authorized position read supplies the timeline counter without changing bounded neighbor reads.

**Tech Stack:** Existing React 19, TypeScript, Mantine 9, TanStack Router/Query, Video.js React 10.0.1, CSS Modules, Fastify/Kysely/SQLite, Vitest and Playwright. No new dependency.

**Spec:** [Shared photo and video theater](../specs/2026-10-20-theater-design.md).

**Status:** Tasks 1–5 implemented and independently reviewed on October 20, 2026. Task 6 production acceptance and required checks are verified. Controller-owned Task 6 and whole-branch reviews remain pending. The approved filtered-timeline counter is implemented. See [production verification](../../theater-verification.md).

## Global Constraints

- Reuse existing React comment components and control presentation with props.
- No copied prototype composer, comment store, reaction pipeline, media loader or player.
- Exactly one live current-media tree, composer, actual-detail query and navigation-key listener.
- Black stage, contained media, 48px Back/title height, 12px title/playback corners, one-line title.
- Edge zones `clamp(80px, 8vw, 112px)`; hover departure 450ms; morph about 390ms.
- Positions displayed as 0:00 mean Whole video. The timestamp's × also clears the anchor.
- Reuse visibility, timeline filters/order, burst traversal, leases, readiness and speculative-loading budgets.
- No route loader for actual detail, migrations, new dependencies, production writes, deployment, push or merge.
- Work in the existing isolated worktree. Preserve the approved prototype and its current refinements.
- Use red/green tests for behavior; inspect screenshots for styles. Do not test hardcoded CSS by restating it in unit tests.
- Keep docs current. Copy the spec, plan and verification artifacts to the matching Downloads folder; render Markdown copies as PDFs.

## Review Focus

1. A denied or slow destination must not expose the previous item's comments or drop the fullscreen host. Tasks 4 and 6.
2. A post settling after navigation must not erase a newer draft or permit a duplicate pending post. Task 2.
3. Portaled reaction pickers and delete dialogs must remain visible, focusable and inside the dock interaction region in fullscreen. Tasks 3 and 6.
4. Comment autofocus/pause must defeat queued autoplay and source renewal, including after media retirement. Task 5.
5. Position counts must match actual filtered neighbor order, with hidden frames, burst/capture-order differences and date boundaries. Task 1.

## Ownership and interfaces

Paths below are relative to the repository. Existing files are extended, not replaced wholesale.

| Owner                                   | Responsibility                                                                                  |
| --------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `ItemSurface`                           | Actual detail, persistent theater host/controller, shared transport and draft-provider lifetime |
| `ItemViewer` / `ItemViewerConversation` | Pass presentation and theater actions to the existing photo/video branches                      |
| `ItemConversation`                      | Change the same media/comment tree between page and theater layout                              |
| `ItemComments` / `ItemComposer`         | Shared content, composer, layout variant and draft hook                                         |
| `TheaterCommentDock`                    | Bubble, morph, opening/focus/dismissal and scoped portals; no writes                            |
| `ItemNavigation`                        | Same neighbor controller and keys, with page or edge presentation                               |
| Existing photo/video owners             | Same media nodes, loading, retry, transport, timeline and reactions                             |

Shared presentation type in `ItemViewer/ItemViewer.types.ts`:

```ts
export type ItemPresentation = "page" | "theater";
```

Components default to `page`. PhotoFrame retains its existing loading-purpose
`presentation` prop and receives a separate `appearance?: ItemPresentation`.
