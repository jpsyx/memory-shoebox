# Media Delivery and Viewer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reuse downloaded media and make nearby viewer navigation ready without speculative product events.

**Architecture:** A bounded lease service is owned by each B2 client/application instance. Catalog representation selection occurs before signing. A member-scoped preview cache and scheduler feed responsive rendering and safe renewal, while the existing detail endpoint remains the actual-open path.

**Tech Stack:** Existing AWS S3 SDK, Fastify/Kysely, Zod, TanStack Query/Router, React, browser image/video APIs.

**Spec:** [Approved design, sections 1-5](../specs/2026-10-14-media-loading-design.md).

## Global Constraints

Inherit every constraint and execution gate in the [master plan](2026-10-14-media-loading.md#global-constraints). In particular: one-hour signatures, seven-day private byte freshness, 10,000 leases, 60-second renewal margin, eight-item batches, 250 ms dwell, two ahead/one behind, two speculative operations, 8 MiB encoded and 32 MiB decoded. Never fetch an original video speculatively.

## Review Focus

Master focus 1-3 belongs here. Also test empty catalogs/zero renditions, mixed video/photo bursts, long-open tabs, and rapid backward navigation; each has a specific owning test below.

## File Structure

`server/src/media/` owns reusable signing and representation policy; `shared/src/mediaPreview.ts` owns safe-read schemas; `web/src/media/` owns member-lifetime preview state, candidate choice, and scheduling. Existing surfaces consume those units rather than implementing separate prefetchers. Tests live beside web units and under `server/test/media/` or `server/test/routes/`. No new service worker or private persistent cache is introduced.
