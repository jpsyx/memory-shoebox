# Family archive motion implementation plan

> Execute inline with the executing-plans workflow. The user authorized reviewing
> the app and implementing the strongest opportunities in this session.

**Goal:** Make handling family photographs feel continuous, tactile and warm.

**Architecture:** Small Web Animations API utilities preserve the current React,
Mantine and router ownership. CSS owns bounded entrances and feedback. Photo
navigation transfers only presentation geometry, never requests media or records
an extra open. No additional dependency or licensed component is required.

**Spec:** The motion direction in this conversation and `docs/motion-review.md`.

## Global constraints

- Preserve uncropped media, seeded resting poses, opaque chrome and four inks.
- Maintain all existing navigation, keyboard, selection and permission behavior.
- Reduced motion keeps short opacity feedback and removes spatial movement.
- No motion delays an API mutation or invents upload completion.
- No production email, uploads, state changes, publication or Git integration.

## Review focus

- A stale photo snapshot must never animate into an unrelated item or account.
- Interrupted animations must restore visibility and release temporary DOM.
- Slow or failed media loading must leave usable content and navigation.
- Repeated burst collapse, selection and keyboard Escape must preserve focus.
- Existing print transforms must compose with motion instead of being replaced.

## Completion record

Implemented in `feat/motion`. Final repository validation: 4,222 tests passed
(250 root, 302 shared, 55 email, 1,714 web, 1,901 server); formatting, lint,
workspace type checking and production build passed.

The independent reviewer verified fixes for interrupted fan geometry, delayed
focus restoration and effect cleanup. Two new WAAPI regressions failed before
those fixes and passed afterward. No material findings remain.

Desktop and mobile browser checks used a local acceptance catalog with disabled
email delivery. They verified photo flights both ways and cleanup, fan opening
and collapse, Escape focus restoration, named arrangement transitions, upload
previews, settled-upload rendering, reduced motion and a missing View Transition
API. No page errors were recorded. Local evidence is under
`.playwright-mcp/motion/` (intentionally gitignored).

Decisions: use original native motion rather than copied React Bits components;
reuse the existing easing token; implement under the user's explicit review and
implementation authorization. Native snapshots replace a custom miniature-layout
interpolator. The tradeoff is an immediate arrangement change in browsers without
the View Transition API. No runtime dependency or license credential was needed.
All review findings were addressed; no minor findings were deferred. Remaining
product opportunities are recommendations in `docs/motion-review.md`.
