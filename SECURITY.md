# Security policy

Memory Shoebox holds photographs of people's children. A vulnerability here is not an
abstract problem, so security reports are taken seriously and handled quickly.

## Reporting a vulnerability

**Please do not open a public issue for a security vulnerability.**

Report it privately through GitHub's
[private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability)
on this repository: go to the **Security** tab and choose **Report a
vulnerability**.

Please include:

- what the issue is and roughly how severe you think it is,
- the steps to reproduce it,
- the version or commit you tested against,
- any suggested fix, if you have one.

You should get an acknowledgement within a few days. Once a fix is released the
advisory is published, and you will be credited unless you would rather not be.

## Supported versions

Memory Shoebox is in early development and has not had a stable release. Until it
does, only the latest commit on `main` is supported. Self-hosters should track
`main`.

## Scope

In scope:

- Anything that lets a person see media, comments, or account data they were
  not invited to.
- Authentication and session handling flaws.
- Injection, path traversal, or SSRF in the server.
- Presigned media URLs being issued to the wrong person, or living longer than
  intended.
- Dependency vulnerabilities that are actually reachable in Memory Shoebox.

Out of scope:

- Findings that require an attacker to already control the instance's
  environment variables, its Backblaze credentials, or its host.
- Denial of service through sheer request volume against a self-hosted
  instance.
- Missing hardening headers with no demonstrated impact.
- Reports generated by a scanner with no evidence of exploitability.

## For self-hosters

A few things are your responsibility, not the software's:

- Keep `SESSION_SECRET` secret, and use a unique value per instance.
- Scope the Backblaze application key to one private bucket, and never make
  that bucket public.
- Serve your instance over HTTPS. Fly.io does this for you by default.
- Update regularly.
